# SETUP 模式流程 spec —— 对话式起草闭环(第 2 步)

> 配套 [setup-mode-design.md](setup-mode-design.md)(为什么)与 [question-drafting-principles.md](question-drafting-principles.md)(每题起草原则)。
> 本文是**第 2 步的实现规格**:把"AI 盲起草 → 机器质检 → 用户拍板 → 冻结"串成可照着走的对话流程。
> 状态:设计已定(2026-06-15 用户拍板 D1–D4),待实现。

---

## 0. 角色与边界

- **"AI 起草"里的 AI = 对话中的 Claude 本身**,照本 spec + 起草规则书做;不是新写的 Python。
- 第 2 步**新代码只有一块**:`aivis init` 脚手架(阶段 5 用)。其余全复用现成:`validate`(质检)/ `load_frozen_config` / `run`。
- **工具是观测器,不是守门人**:质检员只**报告+警告**,**从不替用户拒绝**(见 D2)。

---

## 1. 七阶段流程

### 阶段 0 — 收集输入(Claude 问,对话式)
必填:
- **焦点品牌全名**(明确提示"请给全名,别用简称")+ 常见简称(aliases)+ 歧义简称(Claude 帮判 → `ambiguous_aliases`,**只记录不计分**)
- **焦点域名**(官网)+ 其它自有域名
- **品类/行业描述**(自然语言,如 "project management SaaS")—— 驱动盲起草的唯一输入
- locale / region / 档位(默认 en-US / US / standard)

可选:用户已知的种子竞品。

> 别名保守:默认只有精确全名计分;Claude 建议别名分级,用户确认;拿不准的进 ambiguous(记录不计分)。

### 阶段 1 — 建议竞品集(Claude 起草,用户确认)
- Claude 按品类提竞品名单(名+域名),可借 web_search 落地(SETUP 时允许 AI)。
- 用户加 / 删 / 确认 → 成 brands.yml 的 peer 集(焦点 + 竞品)。盖 `competitor_set_version`。
- **诚实**:漏竞品 → SOV 标注"在声明的 N 个内";跑完后中立题会自审计漏掉的竞品(下一基线补)。

### 阶段 2 — 盲起草 24 题(Claude,照起草规则书)
- 🔒 前 20 中立题:**只依据"品类描述"起草,不为焦点品牌的强项定制场景**。
- 后 4 防御题:起草句式骨架 + 注入焦点品牌名。
- 严格 8/6/6/4,逐题标 intent。
- **推荐(D1 硬化)**:**让用户另起一个新对话窗口专门做起草** —— 新窗口里焦点品牌没进上下文,Claude 起草中立题时更接近"真盲",不易被焦点强项带偏。

### 阶段 3 — 机器质检(draft 档)
- 草稿写进工作配置目录,跑 `aivis validate --phase draft`。
- **必须 0 硬错(含严格 8/6/6/4)**;有错 Claude 自己修、重起草,直到干净。这是 Claude 的自我把关,不打扰用户。

### 阶段 4 — 给用户看 + 改(用户最终拍板)
- 按桶展示 24 题 + 竞品集;Claude 在旁给意见(如"l03 场景偏向某家,建议改中性")。
- 用户自由改(增/删/改写)。改完跑 `aivis validate --phase final`,把结果当**意见**呈现:
  - 🟡 告警(配比不对等)→ 只提醒。
  - 🔴 硬错(中立题点名品牌等红线)→ **弹大声红色警告并解释为什么会污染测量**。

### 阶段 5 — 冻结(写配置 + 版本号)
- `aivis init <name>` 先生成焦点模式骨架;Claude 把确认后的 24 题文本 + 品牌填进去。
- 写 `configs/<name>/questions.yml + brands.yml`,盖版本号 `<name>-YYYY.MM-vN`(如 `acme-2026.06-v1`)。
- 末尾再 `validate --phase final` 复核。**🔴 红错不拦冻结**(见 D2):若仍有红错,Claude 最后一次大声警告"这样冻结会让测量不诚实,确认是你的决定吗?"——用户确认即冻结,责任归用户。
- 这是新基线;**以后任何改动 = 版本号 bump**,不混旧趋势(契约 fingerprint 机械暴露漏 bump)。

### 阶段 6 — 交棒 MONITORING
- 建议先 mock 跑通:`aivis run --config-dir configs/<name>`(零成本)。
- 真实:`aivis run --config-dir configs/<name> --provider anthropic --yes`(过成本闸门)。

## 2. 四个拍板决策(2026-06-15 用户定档)

- **D1 — "盲起草" = 程序性 + 被检查的盲,非密码学级。**
  同一 agent 知道焦点是谁,做不到真隔离。能做:按品类中性起草 + 机器查(中立题无品牌名)+ 用户审(本地场景真实性)兜底。**硬化建议:用户另起新窗口做起草**。真隔离(独立的不知情起草调用)留待未来。**已接受此诚实局限。**
- **D2 — 用户对内容有最终权;破红线只弹红警告、不拦冻结。**
  工具是观测器不是守门人。中立题点名品牌等红线 → 大声红色警告 + 解释危害,但**不替用户拒绝**。是否照此冻结是用户的决定;**不诚实是用户的选择,不是我们的**——我们尽到清晰警告的责任。
  (实现含义:`validate` 仍把红线判为 `error`/红色显示 + 退出码 5 作**信号**,但 SETUP 流程**不把它当硬止**,只展示给用户拍板。validator 代码不变,只是消费侧不拦。)
- **D3 — 代码最小但不省,保稳定。** `aivis init` 脚手架照造、配测试;冻结 = 填骨架 + validate 兜错;若手填易碎再补冻结助手。
- **D4 — 版本号** `<name>-YYYY.MM-vN`。

## 3. 实现分块(第 2 步)

- **2a(代码)**:`aivis init <name>` —— 生成焦点模式配置骨架(24 题按桶标好的空槽 + brands.yml 焦点占位 + 版本号占位)。给阶段 2/5 一个可靠的"填空目标"。配单元测试 + 生成物能过 `validate`(空槽阶段允许的形态)。
- **2b(文档为主)**:把本 spec 阶段 0–6 写进 SKILL.md 的 SETUP 模式,作为 Claude 照走的流程说明书;引用起草规则书 + validate。
- **2c(收尾)**:MONITORING + 成本闸门在 SKILL.md 接好;mock 上把 SETUP→run 整条端到端走一遍验证。

## 4. 未来可硬化(不在第 2 步)

- 把"冻结时仍未解决的红色警告"记进 RunManifest 以便追溯(**触及契约 = 需单独讨论**,不在第 2 步)。
- 竞品自审回路落地为报告里的"看到但未声明的品牌"清单。
