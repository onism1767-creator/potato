# 分发形态决策评审(Distribution Options — for Review)

> 请评审者帮我们判断:这个工具**该以什么形态交付给用户**,以及**隐私安全方案是否站得住**。
> 背景:这是一个**作品集项目,暂无真实客户**。核心诉求是 ① 用户上手极简(怕麻烦)② API key 绝对安全(本地、不上服务器)③ 用户自带 key(我们不垫 API 费)④ 可演示、有产品感(作品集)。
> 已附:我们的纠结点、两个候选方案详述、安全分析、待定问题。

---

## 0. 这个产品是什么(给评审者的 30 秒)

工具叫 **aivis**:测量"一个品牌在 **Claude(开 web 搜索)** 的回答里被**提及/被引用**的频率",输出带不确定区间、可审计的报告(可视化为 HTML)。

架构上是**两层**(这点是理解后面所有取舍的关键):

```
① 测量引擎(CLI / Python 库)   ← 真正干活、真正调 AI API、真正花钱的地方;已基本完成
② 前端 / 交付壳              ← 引导用户、收集输入、展示报告;形态待定(本文要决策的)
```

- 引擎用**用户自己的 `ANTHROPIC_API_KEY`** 调 Claude API 做探测(一次全量 ~72 次调用、**真实花费约 $7**、耗时 **~25 分钟**)。
- 这笔 API 费是 **Anthropic 直接向用户的 key 收**,跟"用户和某个 AI 聊天的 token"是两个账。
- 引擎已内置:成本估算 + 运行时按真实花费硬封顶、配置质检、SSRF 防护、报告生成。开源(MIT)。

## 1. 我们的核心诉求与担忧(决策驱动力)

1. **怕麻烦**:目标体验要像"装个软件 / 注册个 App"那样,**互动步数越少越好**。
2. **API key 极敏感**:用户可能把 key 粘到任何地方;**一旦做成托管网站/App,key 就会传到/留在我们服务器上 = 安全雷**。所以**坚持本地**:key 本地输入、本地保存、本地用。
3. **用户自带 key**:我们不替用户垫 API 钱(也就不必做计费系统)。
4. **作品集**:要**能看见、能演示、有产品感**,不是一堆命令行截图。
5. **跑一次 ~25 分钟**:任何前端都得是**异步**体验("提交 → 回头看报告"),不是点一下立刻出。

> 基于第 2、3 条,我们**已排除"托管网站 / SaaS / 云端 App"**:那会把 key 和数据带上服务器,违背安全底线,且要垫资+做计费,对一个无客户的作品集不划算。**所以两个候选都坚持"本地运行、key 不出本机"。**

## 2. 两个候选方案(都本地、key 都不出本机)

### 方案 A:Claude Skill(对话式引导)

- **形态**:一个 `SKILL.md` + 现成 CLI。用户在 **Claude Code** 里使用,Claude 照 SKILL.md 一步步**在聊天里**引导(收集品牌→建议竞品→起草问题→质检→跑→读报告)。
- **用户怎么用**:装 Claude Code + 装我们的包 + 把 key 配进本地环境变量 → 在聊天里对话完成。
- **key 处理**:本地环境变量,Claude Code 本地运行,key 不出本机。
- **优**:几乎现成(引擎 + SKILL.md 已做);展示"懂 Claude 生态";维护成本低。
- **劣**:**界面就是聊天框,不可视**(作品集观感弱);要求用户会用 Claude Code(对"怕麻烦"用户仍有门槛);引导是对话式,不是有按钮的向导。

### 方案 B:本地 GUI 向导 + 一键安装包(作者倾向)

- **形态**:一个**本地桌面小程序**,双击一个**一键安装包**装上(内置引擎),全程本地运行,最后在本地打开 HTML 报告。
- **用户怎么用(精简向导,大多数字段有默认值/可跳过)**:
  - **Step 1**:填品牌名 / 域名 / 品类
  - **Step 2 设置**(互动最少化):烧钱版 vs 普通版(预算开关)· **当场显示成本估算**("这次约 $X")· 可选填竞品 · 可选填模糊名/缩写
  - **Step 3**:填一次 API key(存本地)
  - 一个"开始"按钮 → 异步跑(~25 分钟,显示"运行中,回头来看")→ 弹出本地 HTML 报告
- **key 处理**:存**操作系统钥匙串**(加密落盘),只直发 `api.anthropic.com`。
- **优**:**可视、可演示、有产品感**(作品集最强);上手像装普通软件(最贴合"怕麻烦");把"本地+key 安全+精简引导"全落地。
- **劣**:要**新做一个薄前端**(引擎全现成,但 GUI + 打包是额外工作量);桌面安装包本身是一个需要被信任的二进制(见 §3 的缓解)。

### 一句话对比

| | A. Claude Skill | B. 本地 GUI 向导 + 安装包 |
|---|---|---|
| 引导形态 | 聊天里逐步问 | 可视化 Step 1/2/3 向导 |
| 上手门槛(怕麻烦) | 中(需 Claude Code) | 低(装个软件) |
| 作品集观感 | 弱(md + CLI) | 强(可演示的产品) |
| key 安全 | 本地环境变量 | 本地钥匙串 |
| 工作量 | 几乎现成 | 需做薄前端 + 打包 |

> 注:两者**共享同一个引擎**,不是互斥——可以先做 B 当主秀,再补 A 展示"一套核心、两种前端"的架构能力。

## 3. 隐私 / 安全方案(重点请评审者挑战)

**核心逻辑:本地 + 开源 = 把"相信我"换成"你自己能查"。** 具体保证:

1. **API key**:存系统钥匙串(OS 加密),**明文不落盘、永不写日志、不硬编码进安装包**;只发往 `api.anthropic.com`(TLS),不经任何第三方、不经我们。本质就是用户自己 Anthropic 账户的 key,我们不当中间人。
2. **零遥测 / 零回传**:App 只对两类地址发请求——`api.anthropic.com`(探测)+ 被引用的第三方页面(仅核验时)。**对开发者服务器一个字节都不发**(无分析/无崩溃上报/无追踪)。因为开源,这点**可被审计验证**,不是口头承诺。
3. **数据全本地**:原始回答 / 证据 / 报告都写在用户本机,随时可删,不上传。
4. **可审计 + 可信分发**:代码开源(MIT);一键安装包计划**从开源代码可复现构建** + **代码签名**(用户知道"这个 exe = 我审过的源码")。
5. **抓取的第三方页当不可信数据**:已有 SSRF 防护(只允 http(s)、拦私网、逐跳重定向校验)+ HTML 消毒(绝不把生 HTML 当指令喂模型,防 prompt 注入)。
6. **诚实披露(绕不开的部分)**:要测 Claude 可见度,问题**必须发给 Anthropic**——在用户**自己账户**下,跟正常用 API 一样;用户填的品牌/竞品名只在本地用于造问题+检测,**不发给我们**。

**已知安全边界(诚实)**:当前不做 DNS pinning / 不防 DNS rebinding / 不解十进制 IP 混淆——适用于**本地工具**威胁模型;若哪天做成公网服务,这块要升级为 P0。

**一个可当卖点的透明度功能**:报告里放"本次网络去向"面板——"本次 72 次 → api.anthropic.com,11 次抓取 → 这些被引域名,**0 次发往其它地址**"(数据来自已有的 RunManifest)。把透明度做成看得见的功能。

## 4. 我们已达成的共识 / 仍待定

**共识**
- 坚持**本地运行、key 不出本机**;**排除托管网站/SaaS**。
- 用户**自带 key**;不做计费。
- 引擎(测量+成本闸门+质检+报告)**已基本完成**,前端是薄壳。
- **HTML 报告**是两方案的公共下一步,先做不亏。

**待定(想听评审者意见)**
- 主前端选 **A** 还是 **B**?(作者倾向 B,理由见 §2)
- B 的 key 本地存储:**系统钥匙串** vs 加密本地文件,哪个更稳妥?
- 一键安装包的**信任问题**(二进制):开源+签名+可复现构建够不够?还需要什么?
- "怕麻烦"与"安全"之间,B 的 Step 1/2/3 是否还能再砍互动?

## 6. 评审结论与落地路线(已采纳 2026-06-16)

外部评审建议**主方案选 B,但分阶段、先轻后重**,A 降为"专家入口"保留。已采纳。

- **主方案 = B**(本地 GUI 向导 + HTML 报告);**不一上来做重型桌面 App**。
- **A(Claude Skill + CLI)= 专家入口**,展示 Claude 生态能力 + 给技术用户,不作作品集主秀。
- **对外定位(统一口径)**:"aivis 是一个**本地运行、用户自带 API key、可审计**的 Claude web-search 可见度测量工具,生成带不确定区间和证据链的 HTML 报告。" 不说"AI 排名真相检测器",不承诺"照做就能提升排名"。

**四阶段最小落地路线**:
1. **Phase 1 ✅(commit 82f4747→51e09e7)= 项目官方 HTML 模板(用户最终所见)**:`render_html()` —— 单文件、零外链、无脚本的淡橙 dashboard HTML 报告,**英文**(受众不同);内联 SVG 排名条(带 Wilson 区间)+ SOV 甜甜圈;**数据由 ScoreBundle 驱动(非静态)**,外部数据 HTML 转义防注入;`aivis run`/`report` 自动用真实数据写出 report.html(引擎↔模板已通);已验证数据正确性 + 数据驱动;e2e 测试断言单文件+离线。改模板=改 render_html。
2. **Phase 2**:`aivis gui` 本地向导 —— **只监听 127.0.0.1**,浏览器开本地页;收集品牌/域名/品类/预算/key,后台调现有 CLI/库;跑完打开本地 HTML 报告;异步任务 + 成本估算。
3. **Phase 3**:`keyring` 系统钥匙串存 key + 报告里"**本次网络去向**"面板 + 明确"无遥测"声明。
4. **Phase 4**:Windows 安装包(先用 Python 打包工具,非 Electron/Tauri)/ 签名 / 发布说明。

**隐私安全落地要点**:key 默认存**系统钥匙串**(非本地加密文件)· 不做托管 SaaS / key 不经我们服务器 · 无遥测/无崩溃上报/无第三方 analytics · HTML 报告加"网络去向"面板。

**🟥 发布前必须先处理(最大扣分点)**:删除项目目录里的明文 `.env.txt` 并 **rotate** 该 key(已核实它从未进 git 历史,但仍须处理)。

**为何不做"纯网页 + 浏览器直连 Anthropic"**:Anthropic 官方 SDK 默认**关闭浏览器端支持**(防 secret API key 暴露),故不适合作主方案。
