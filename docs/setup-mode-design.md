# SETUP 模式设计决策 —— 跨品类问题生成的"人工拍板"闭环

> **状态:设计已定,尚未实现(2026-06-15)。** 这是一份**决策记录 + 待办设计**,不是已落地行为。
> 已实现的现货是:背包品类 demo 的 24 题 + 5 中立品牌 + 完整管线(probe→…→report)。
> 本文记的是"如何让任意用户、任意品类、填自己品牌也能用"这个**新功能**怎么造。

---

## 1. 要解决的核心矛盾(不可能三角)

产品同时要三样,天然互相拉扯,**不能同时拉满**:

| 目标 | 含义 |
|---|---|
| 泛用性 | 任何品牌/品类都能用,不只背包 |
| 自动化 | 少人工、可规模化 |
| 真实性 | 测量不被诱导/不灌水,保守计数,不造假精确 |

打架的根:泛用 + 自动 → 必须让 AI 现场生成"问题 / 别名 / 竞品集",而这三样**恰恰最容易污染真实性**(AI 自己生成又自己测 = 既当运动员又当裁判)。

**拍板:三角里主动舍掉的是「完全零人工」,绝不舍「真实性」。** 真实性是本工具唯一的护城河,舍了就只剩一个会编数据的玩具。用"一次性 SETUP 审核 + 逐步沉淀品类模板库"把人工成本压到最小。

---

## 2. 已决定的方案:AI 起草 → 人工拍板 闭环(用户拍板)

**🔒 决策锁定(2026-06-15 用户拍板,"一定要这样"):全部 24 题、四个桶都由 AI 按用户行业现起草,没有一桶写死。**
尤其 **local 场景题、brand_defense 防御题也必须 AI 起草**(它们最吃行业语境,写死就无法泛用)。
用户拥有完全修改权、自己编辑、最终拍板;AI 建议在旁辅助。这是把工具从"只能测背包"变成"任何行业可测"的核心机制。

**AI 起草照哪份规则?→ [question-drafting-principles.md](question-drafting-principles.md)**(每桶起草原则 + 句式模板 + 机器校验闸,一处三用:AI 指令 / 用户审核清单 / 代码护栏)。

```
用户给:焦点品牌全名+域名+别名、品类描述、(可选)种子竞品
   ↓
① AI 盲起草        起草时【不告诉 AI 焦点品牌是谁】→ 它无法偏向你
   ↓               焦点品牌名只在最后注入 4 道"品牌防御"题
② 机器校验闸        代码(非人)先挡明显错:
   ↓               · 强制 8/6/6/4 配比
                   · 断言前 20 道中立题【不含任何品牌名】(焦点+竞品全集正则)
                   · 挡掉明显引导句式
③ 用户看 → 改 → 拍板  用户看一眼生成的问题,有完全的修改权,自己编辑、最终拍板
   ↓               (AI 可在旁给建议,但人是最后决定者)
④ 冻结             写入 questions.yml / brands.yml,bump prompt_version /
                   competitor_set_version → 成为一条新基线
   ↓
⑤ 照常测量          probe→extract→verify→score→report,100% 自动确定性
```

**关键不变量**:
- **人(用户)永远是最后拍板者**,AI 只出草稿和建议,绝不自动冻结。
- **全部 4 桶都 AI 起草**(含 local / brand_defense),但**盲起草只针对前 20 道中立题**(起草时不知道焦点是谁,无法偏向);brand_defense 的 4 道是 AI 起草"句式骨架"(如 "Is {X} a good …? strengths and weaknesses?"),再把焦点品牌名填进 {X}。两件事不冲突。
- **盲起草**是结构性防偏置:中立题的起草环节不知道焦点是谁。
- **测量轨保持纯**:AI 起草是 SETUP 一次性动作,人工确认后冻结,**绝不进测量管线**(呼应 CLAUDE.md §7.1 —— AI 仅允许在 SETUP 起草问题/建议竞品,人工确认后冻结)。

## 3. 三个具体污染点 × 守法(对应不可能三角的"真实性")

**① 问题质量 / 隐性引导**
- 🟢 **AI 现起草 + 用户拍板(B,泛用性的来源)**:全部 4 桶按行业现生成,用户审改
- 🟢 盲起草(见上)+ 机器可检规则(8/6/6/4、前 20 题无品牌名)
- 🟡 二次 AI"引导度"评分仅供人工参考,**不当闸**(AI 评 AI 不进指标)
- 🟢 (可选后期)品类模板库:高频行业沉淀人工审过的题集复用 → 边际人工趋零;非必须
- ⚠️ 残余:每个新行业仍需一次人工审 24 题(~5–10 分钟)—— "真实性"省不掉的代价

**② 别名 / 歧义(Apple = 品牌 or 水果)**
- 🟢 保守默认:默认**只有精确全名算清晰名计分**,其余先进 ambiguous(记录不计分),除非用户显式提升 → **没人工时也绝不多算**
- 🟢 Wilson 区间 + "无法区分"规则吸收噪声
- ⚠️ 残余:别名只影响召回(可能少算),**不影响精度(不会多算)**,偏在保守方向 → 符合诚实红线

**③ 竞品集漏一个 → SOV 虚高**
- 🟢 口径诚实:SOV 永远标注"在你声明的 N 个品牌内的份额",**绝不冒充绝对市场份额** → 漏报是透明口径不是谎
- 🟢 自审回路:中立发现题会自发提到用户没声明的品牌 → 挖出"看到但未声明的品牌"反馈 → 下一基线补(**中立题自审计竞品集完整性**)
- 🟢 开放世界双指标:焦点既报"绝对提及率"(免疫漏报)又报"相对 SOV"(需竞品集)
- ⚠️ 残余:首版竞品集仍需人工拍,但有自审回路兜底 + 口径诚实

## 4. 战略旋钮(留给 PM,影响"对外承诺几分真实")

- A. 全自助(用户盲信 AI 生成 config 直接跑)—— 最自动、真实性最弱,**撞诚实红线,不采用**
- **🔒 B. AI 起草 + 人工确认闭环 —— 已锁定为核心机制(2026-06-15 用户拍板)。每来一个新行业,AI 现场起草全部 24 题,用户审核/编辑/拍板。这是泛用性的来源。**
- C. 人工审过的品类模板库 —— **降级为"可选的后期加速",不是必须**。某些高频行业可把审过的题集存货架复用,但核心永远是 B 的"现起草 + 用户拍板"。

路线:**B 是地基且长期保留;C 只是 B 之上的可选缓存层,有余力再做。**

## 5. 落地分步(未开工,顺序建议)

1. **第 1 步(小、稳):** BYO 焦点支持 + 机器校验闸。让肯自己写 YAML 的用户现在就能用,并把"反偏置 / 8-6-6-4 配比 / 一个 is_focal / 保守别名默认"做成**代码强制护栏**。改动小、全在现有结构内、可测试。
2. **第 2 步(大、泛用性主体):** SKILL SETUP 模式 —— Claude 引导填品牌、AI 盲起草竞品+问题、机器校验、用户看/改/拍板、冻结。这步要一个**对话式逐条确认循环**,天然属于 SKILL 而非纯 CLI。

契约现状(利好):`Brand.is_focal`、`FrozenConfig.focal_domain`、`competitors_on` **早已在 contracts 里预留**,数据模型层面几乎现成 —— 工作量主要在"人工确认闭环"的交互与护栏,不在数据结构。

## 6. 与现状的关系(防止再次"晕")

- **现货**:背包 demo 已完整可跑,24 题+5 品牌都是实打实写好的,不是空模板;`--config-dir configs/demo` 即出真报告。demo **没有焦点品牌**,测的是 5 个同行间的份额。
- **本文功能**:在现货之上**加一层 SETUP**,让任意用户填自己品牌、为自己品类生成问题。**与现有管线解耦**,管线本身不改口径。
